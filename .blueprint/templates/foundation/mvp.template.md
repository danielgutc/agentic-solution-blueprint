## Purpose

Define the smallest useful production-quality version 1.0 and the priority model for sequencing work. Requirement-level priority, target, and status belong in [Requirements](./requirements.template.md).

## Version 1.0 baseline

Follow the [MVP quality policy](../../instructions/standards/mvp-quality.md). The implemented scope uses the approved final technical architecture and establishes a foundation that the known roadmap can extend without a prerequisite corrective rewrite. Defer features instead of lowering engineering standards. Keep PoC-only shortcuts and evidence separate from release acceptance; routine refactoring and reviewed evolution for new requirements remain possible.

## Priority model

| Priority | Meaning | Selection rule |
| --- | --- | --- |
| P0 MVP | Required for production-quality version 1.0. | Directly enables feedback or proves a blocking dependency. |
| P1 Next | Candidate after MVP feedback. | Extends the validated slice toward the next user outcome. |
| P2 Later | Valuable after near-term feedback. | Deepens capability without blocking the first learning loop. |
| Experiment | Intentionally uncertain. | Build only enough to make a decision. |
| Deferred | Outside the current planning horizon. | Explicitly excluded from current sequencing. |
